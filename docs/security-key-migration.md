# 加密密钥迁移说明

在推送或部署移除仓库内 `secret.key` 的提交前，必须同时备份现有数据库和与其匹配的 `secret.key`。两者应作为一组恢复，并保存在受控的安全位置。

如果默认 SQLite 数据库已存在，但运行时找不到 `secret.key`，后端会拒绝启动。此时必须恢复与该数据库匹配的原密钥，不能生成新密钥替代，否则旧密文将无法解密。

Git 历史中曾提交过的旧密钥应视为已经泄露。请在受控维护窗口中轮换密钥，并重新录入 Cookie、邮件凭据及其他敏感配置，确认业务恢复后再结束维护。

清理 Git 历史会改写提交记录并影响所有协作者，必须作为独立操作另行确认后执行。
