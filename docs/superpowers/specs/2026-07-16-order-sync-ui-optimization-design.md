# 订单同步任务优先 UI 优化设计

## 背景

当前订单同步页把使用说明、CookieCloud 配置告警、熔断告警和账号操作平铺展示。页面虽然功能完整，但存在三个直接影响日常使用的问题：首屏说明过长、异常恢复路径被多层告警稀释、单个账号的九项操作在表格末列堆叠且窄屏只能横向滚动。

本次采用已确认的 **A 方案：任务优先控制台**。目标是让用户进入页面后先看见“是否需要处理、处理哪个账号、下一步做什么”，再按需阅读同步说明。

## 成功标准

1. 首屏直接展示账号总数、待处理账号数、自动同步账号数和服务状态。
2. 已熔断账号以明确的三步恢复路径呈现：更新 Cookie → 校验 → 恢复。
3. 同步说明和 Cookie 获取方法默认折叠，不再占据首屏主要空间。
4. 账号操作按当前状态分级：主操作常显，镜像、日志、删除等次要操作收进“更多”。
5. 桌面宽度下无需 1280px 横向表格才能完成主要操作；小于 768px 时账号内容自然单列堆叠。
6. 不改变任何同步、恢复、Cookie 校验、自动同步或删除业务逻辑及 API 契约。

## 页面结构

### 1. 顶部工具栏

- 保留“订单同步”标题、后端连接状态、CookieCloud 状态、添加账号和刷新。
- 服务状态使用紧凑标签，添加账号仍是唯一主色按钮。
- 标题区不重复展示账号业务异常，异常统一进入下方任务区。

### 2. 状态总览

新增四项紧凑总览：

- 全部账号：`accounts.length`。
- 待处理：状态为 `paused`、`invalid` 或 `risk` 的账号数。
- 自动同步：已开启且未暂停的账号数。
- 服务状态：后端连接状态和 CookieCloud 是否启用。

总览只做现有数据的派生展示，不新增请求或持久状态。

### 3. 待处理任务区

- 有熔断账号时显示高优先级恢复任务，列出账号昵称和固定三步路径。
- CookieCloud 未启用时显示次一级配置提示，保留“重新检测”，详细缺失项放入可展开内容。
- 没有异常时不保留空告警容器。
- 最近一次订单/商品同步结果继续使用现有 Alert，仅在对应操作后出现。

### 4. 使用帮助

原“闲鱼同步说明”改为默认收起的帮助面板，内容保持不变，分为：

- 订单与商品同步行为。
- 自动同步与风控安全边界。
- Cookie 获取方法。

帮助面板不遮挡任务区和账号列表。

### 5. 账号卡片网格

用响应式账号卡片替代固定宽度操作表格：

- 桌面：`auto-fit` 网格，每张卡最小宽度约 360px。
- 平板/手机：单列展示，不产生页面级横向滚动。
- 卡片头：昵称、账号 ID、状态标签。
- 状态摘要：上次同步、自动同步开关与间隔、连续失败计数。
- 最近错误：有错误时使用低饱和危险色区域，无错误时不占位。
- 操作分级：
  - 熔断账号：常显“更新 Cookie”和“校验并恢复”。
  - 正常账号：常显“同步订单”和“同步商品”。
  - “更多”菜单：校验、订单镜像、商品镜像、日志、编辑、删除。
- 删除仍保留二次确认；恢复仍保留现有前置条件说明。

为保持调用边界稳定，现有容器回调继续通过 props 注入。`AccountTable.tsx` 可改名为 `AccountCardGrid.tsx`，不把 API 调用下沉到展示组件。

## 视觉方向

- 延续当前闲鱼橙主题，不引入新品牌色或外部字体。
- 页面背景保持中性灰，任务区与账号卡使用白底、细边框和轻阴影建立层级。
- 危险状态使用低饱和红色背景配合文字和图标，不能只依赖颜色表达。
- 减少大面积 Ant Design Alert 的连续堆叠，改用更紧凑的任务面板。
- 动画仅用于卡片悬停和帮助面板展开，并继续尊重全局 `prefers-reduced-motion`。

## 可访问性

- 每张账号卡使用可识别的区域标题。
- 纯图标操作必须提供 `aria-label`；“更多”菜单项使用完整文本。
- 状态数字同时提供文字标签，不仅通过颜色区分。
- 键盘可访问帮助面板、菜单、确认弹层和所有主要操作。
- DOM 顺序与视觉顺序一致，移动端不通过 CSS 重排改变阅读顺序。

## 错误与空状态

- 后端离线和检测中状态保持现有 Result/Spin 逻辑。
- 账号加载失败继续使用现有消息提示，不伪造空账号成功状态。
- 无账号时显示带“添加账号”入口的明确空状态。
- CookieCloud 状态请求失败时总览显示“状态未知”，不误报为已启用或未启用。

## 测试与验证

### 自动化测试

1. 先新增失败测试，验证总览计数和异常任务派生逻辑。
2. 组件测试验证：
   - 熔断账号显示“更新 Cookie”和“校验并恢复”。
   - 正常账号显示同步主操作。
   - 次要操作位于可访问的“更多”菜单。
   - 无账号时显示空状态。
3. Playwright 使用模拟账号数据验证桌面和 390px 视口，不读取真实 Token、Cookie 或业务数据。
4. 运行前端全量 Vitest、TypeScript 检查和生产构建。

### 运行态验证

- 重建 `web` Docker 服务。
- 在真实部署页面确认总览、异常任务、帮助折叠、账号操作和窄屏布局。
- 只读验证页面和健康接口；不触发真实同步、恢复、编辑或删除。

## 范围外

- 不修改后端、数据库、同步调度器或 CookieCloud 配置方式。
- 不自动修复账号 Cookie，也不批量恢复账号。
- 不调整全站主题、导航或其他业务页面。
- 不处理既有 npm 依赖漏洞和 Vite 分包告警。
