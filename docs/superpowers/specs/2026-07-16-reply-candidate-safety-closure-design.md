# 回复候选安全闭环设计

## 决策

在现有回复助手上增加两层候选风险检查：生成候选时检查后端产出的原始回复，复制前再由后端检查用户编辑后的最终文本。风险文本必须经过显式二次确认才能写入剪贴板。

本轮不增加闲鱼消息读取、自动发送、模型重试、会话持久化或新的数据库表。

## 目标与成功标准

- 固定规则和 AI 生成的候选都接受输出侧风险检查。
- 用户编辑后的最终候选在复制前重新检查，避免编辑内容绕过提示。
- 正常候选保持一键复制；风险候选取消确认时不得写入剪贴板。
- 风险复检不调用 AI、不保存正文、不在日志或审计记录中写入正文。
- 风险复检失败时不自动复制，并提示用户可手动选择文本。

## 后端设计

### 生成阶段

`generate_suggestion` 分别对买家最新消息和生成候选调用现有 `classify_risk`，按既有类别合并风险原因并去重。只要任一文本触发风险，响应的 `risk_level` 就是 `manual_required`。

规则匹配和 AI 调用顺序保持不变。输出检查不改变候选正文，也不触发额外模型请求。

### 最终文本复检

新增受现有 API Token 保护的接口：

- `POST /api/reply-assistant/risk-check`

请求：

```json
{
  "text": "用户编辑后的最终候选"
}
```

`text` 去除首尾空白后必须为 1–1000 个字符。

响应：

```json
{
  "risk_level": "normal",
  "risk_reasons": []
}
```

接口只执行本地关键词分类，不访问数据库、AI、闲鱼网络或外部 URL，不记录请求正文。输入校验失败沿用 FastAPI 422；不新增业务错误码。

## 前端设计

回复服务新增 `checkReplyRisk(text)`。用户点击“复制候选回复”时：

1. 对当前编辑后的候选调用风险复检。
2. 返回 `normal` 时直接写入剪贴板。
3. 返回 `manual_required` 时弹出确认框，列出风险原因，主按钮文案为“已核对，继续复制”。
4. 用户取消时不写入剪贴板。
5. 接口失败时不写入剪贴板，显示“风险检查失败，请手动选择文本”。

候选生成后的现有风险提示继续保留。复制按钮在复检期间显示加载状态，防止重复请求和重复确认。

## 数据与隐私边界

- 风险复检文本只在浏览器与本项目后端之间传输。
- 文本不写数据库、操作日志、审计日志、URL 或浏览器存储。
- 接口不接受账号 ID、商品 ID、买家 ID、Cookie、会话 ID 或外部地址。
- 不新增迁移，不改变 AI 密钥处理和现有审计结构。

## 错误处理

- 空文本或超过 1000 字：HTTP 422，前端不复制。
- 后端不可用或响应异常：前端不复制并给出手动选择提示。
- 剪贴板 API 失败：保留现有“复制失败，请手动选择文本”提示。
- 风险确认取消：视为正常用户操作，不显示错误。

## 测试与验证

### 后端

- 规则候选的输出风险与买家输入风险合并并去重。
- AI 候选自身触发风险时返回 `manual_required`。
- `/risk-check` 正常文本和风险文本返回稳定结构。
- `/risk-check` 拒绝空文本和超长文本。
- 风险复检不调用 AI、数据库或审计日志。

### 前端

- 正常最终文本复检后直接复制。
- 编辑后的风险文本触发二次确认。
- 取消确认不写剪贴板，确认后只写一次。
- 风险复检失败不写剪贴板并显示提示。
- 复检期间阻止重复点击。

- 后端、前端全量测试和生产构建通过。
