# 基础访问与 UI 闭环设计

## 目标

在不扩展业务模块、不改变数据库和闲鱼同步安全边界的前提下，依次补齐统一认证入口、移动端完整导航、长表单防丢、系统运行状态、可访问性基础和关键流程端到端冒烟，使现有功能真正可进入、可发现、可恢复、可验证。

## 已批准方向

用户已批准按 2026-07-15 只读审查的优先级连续推进，并要求确认项统一留到最后。本设计采用“集中基础能力 + 逐项闭环”，不采用逐页面复制认证/错误逻辑，也不进行整站视觉重做。

## 方案比较

1. **集中基础能力（采用）**：认证在应用根节点统一处理，移动导航在布局统一处理，运行状态复用既有 `/api/metrics`。改动集中、能覆盖全部页面，回归面清晰。
2. **逐页面修补**：每页自行处理 401、导航和错误。短期直观，但会重复请求、重复文案并持续漏页，不采用。
3. **整站路由与设计系统重做**：可一次重塑信息架构，但会与当前脏工作区和既有业务页面大面积冲突，超出本轮必要范围，不采用。

## 架构与数据流

### 统一认证入口

- `AuthGate` 位于 `ConfigProvider` 内、`RouterProvider` 外。
- 启动时调用白名单端点 `/api/auth/token-status`：后端不可达时显示离线重试；当前会话无 Token 时显示解锁表单；存在 Token 时进入应用。
- 用户输入 Token 后调用 `/api/auth/verify-token`，校验通过才写入现有 `sessionStorage`。
- `apiClient` 收到任何 401 时清除失效 Token，并发出同页认证失效事件；`AuthGate` 立即收回业务界面。
- 不增加“永久记住 Token”，保持当前关闭浏览器即清除的安全语义。

### 移动端完整导航

- 保留现有五项底部主导航，避免改变高频入口和挤压触控面积。
- 移动端页头增加“全部导航”按钮，打开 Drawer，复用完整桌面菜单及待办徽标。
- Drawer 选择页面后立即关闭；底部导航增加 `safe-area-inset-bottom`，内容区同步留足底部空间。

### 长表单防丢

- 新增通用 `useUnsavedChanges` hook，组合 React Router blocker 与浏览器 `beforeunload`。
- 第一阶段接入交易新增/编辑表单；只有用户实际改动后才阻止离开。
- 保存成功或“保存并继续”成功后解除/重置 dirty；校验失败和接口失败仍保留保护。
- 不引入本地草稿和自动保存，避免扩大数据一致性范围。

### 系统运行状态

- 新增薄服务读取既有 `/api/metrics`，不修改后端 schema。
- 设置页新增“运行状态”Tab，展示同步调度器、账号状态、24 小时同步、最近同步错误、最近备份、备份数量和未读通知。
- 加载失败显示可重试错误，不伪装成 0；备份页原有不存在的 “Metrics 页”提示改为真实入口。

### 可访问性基础

- 布局增加跳过导航、语义化 `nav`、可聚焦的 `main` 和全局页面 `h1`。
- 高频交易/客户列表的纯图标操作补 `aria-label`；详情跳转改为真实 `Link`。
- 可点击统计卡改为键盘可达的链接语义；动画尊重 `prefers-reduced-motion`。
- 本轮只处理全局和最高频断点，不对全部历史页面做视觉重构。

### 端到端冒烟

- 使用 Playwright Test 启动独立 Vite 端口，网络层拦截后端 API，不读取真实 Token、客户或订单数据。
- 覆盖：无 Token 显示解锁、正确 Token 进入首页、移动端完整导航可发现、基础语义结构存在。
- 真实 Docker 只用于最终只读冒烟，不在测试中迁移或写入真实数据库。

## 错误处理

- 认证失败、后端离线和普通业务错误分层展示。
- 401 不再由每个页面重复弹出；认证门接管后停止挂载业务路由。
- 指标失败保留最近页面结构但明确显示失败与重试，不显示虚假的健康值。
- 表单离开确认只在 dirty 时出现，保存成功后不误拦截。

## 测试策略

- 每项行为按 RED → GREEN：先写 Vitest/组件或纯函数测试并确认预期失败，再写最小实现。
- 聚焦测试后运行 `npm run check` 和前端全量测试。
- Playwright 使用完全模拟数据；最终再对已运行 Docker 做无业务写入的页面冒烟。
- 不为通过测试修改真实数据、读取敏感字段或关闭认证。

## 非目标与确认边界

- 不增加多用户/RBAC、永久 Token、PWA、库存、AI 功能或新财务口径。
- 不修改数据库、迁移、Cookie、MTOP 调用、同步频率和封控策略。
- 不提交、不推送、不部署；这些动作统一留到最后由用户确认。
- 不覆盖当前工作区已有页面拆分、审计和后端改动。

## 验收标准

- 新会话不会在显示解锁页时批量请求受保护业务接口。
- 移动端能从可见入口到达全部一级页面。
- 交易表单有改动时离开会确认，保存成功后正常跳转。
- 设置页能读取并解释 `/api/metrics`，备份提示不再指向不存在页面。
- 主布局具备 `nav`、跳过导航、`main` 和 `h1`；高频列表操作有可访问名称。
- 类型检查、全量前端测试、Playwright 冒烟和只读运行态检查通过。
