# 闲鱼回复助手 MVP 设计

## 决策

第一阶段在现有项目内增加“闲鱼回复助手”，提供规则匹配、AI 候选回复、人工确认复制和脱敏审计。第一阶段不读取闲鱼聊天页面、不连接闲鱼 IM WebSocket、不自动发送消息，也不创建 Chrome 扩展。

Chrome MV3 薄桥接属于后续独立子项目。只有本阶段经过真实使用验证，且用户再次确认平台协议与账号风险后，才为插件单独编写设计和实施计划。

## 目标

- 用户可选择闲鱼账号和商品模板，粘贴买家消息并获得一条可编辑的候选回复。
- 固定规则优先于 AI，常见问题不依赖外部模型即可得到稳定结果。
- AI 仅通过后端调用 OpenAI-compatible Chat Completions 接口，密钥不进入浏览器存储和前端响应。
- 每条候选都明确标记来源和风险等级，所有发送动作由用户在闲鱼官方客户端或网页中人工完成。
- 默认不保存买家原文、对话上下文或模型完整响应；操作日志只记录必要元数据。
- 保持现有订单同步、商品镜像、交易投影、Cookie 和风控逻辑不变。

## 非目标

- 自动读取未读消息、自动切换会话或自动点击发送。
- 逆向或连接 `wss://wss-goofish.dingtalk.com/`。
- 获取、导出或共享闲鱼 Cookie。
- 绕过验证码、滑块、设备校验、平台限流或其他风控。
- 自动议价、自动承诺退款、自动处理投诉或售后责任。
- 在首个版本中支持图片识别、语音、群聊、多轮会话持久化或模型供应商专有协议。

## 用户流程

1. 用户在“回复助手”页面选择一个已配置的闲鱼账号，可选关联商品模板。
2. 用户粘贴买家最新消息；需要上下文时，可额外粘贴最多 10 条近期对话。
3. 前端提交建议请求，后端先执行敏感意图识别，再按启用规则的优先级匹配。
4. 命中规则时直接返回固定回复；未命中且 AI 已启用时，后端结合商品摘要生成候选。
5. 页面显示候选回复、来源和风险提示。用户可编辑并复制，再到闲鱼官方客户端或网页手动发送。
6. 后端记录“生成候选”的脱敏审计事件，不记录买家原文；复制只发生在浏览器本地，不额外调用审计接口。

## 架构与边界

### 后端模块

新增独立 `reply_assistant` 业务边界：

- `models/reply_assistant.py`：回复助手配置和回复规则。
- `schemas/reply_assistant.py`：配置、规则和建议请求/响应契约。
- `services/reply_assistant_service.py`：输入校验、敏感意图识别、规则匹配、商品上下文构造和候选编排。
- `services/llm_client.py`：唯一的外部模型调用边界。
- `routers/reply_assistant.py`：配置、规则 CRUD 和生成建议接口。

模块可依赖现有账号和商品模板的公开模型/服务，但不得调用 MTOP、同步调度器或解密闲鱼 Cookie。`llm_client` 不得依赖 FastAPI、SQLAlchemy 或闲鱼模型，便于独立测试。

### 前端模块

新增一级页面 `/reply-assistant`，包含三个聚焦区域：

- 候选生成：账号、商品模板、买家消息、可选上下文、生成按钮。
- 结果区：候选文本、来源、风险提示、编辑和复制。
- 配置抽屉：AI 开关、模型配置、系统提示词和固定回复规则。

第一阶段只新增这一个入口，不改订单同步页、设置页和交易表单。

## 数据模型

### `reply_assistant_settings`

单例表，固定 `id=1`：

- `enabled`：回复助手总开关，默认 `false`。
- `ai_enabled`：AI 候选开关，默认 `false`。
- `api_base_url`：仅允许 `https`；本机地址额外允许 `http://127.0.0.1` 和 `http://localhost`。
- `api_key`：使用现有字段加密工具加密存储；读取接口只返回 `api_key_configured`，永不返回密钥。
- `model`：模型名称，非空且最长 100 字符。
- `system_prompt`：全局客服约束，最长 4000 字符。
- `request_timeout_seconds`：固定由代码控制为 20 秒，不开放页面配置。

更新配置时，空 `api_key` 表示保留原密钥；显式 `clear_api_key=true` 才删除。配置修改写入现有操作审计日志，但日志只记录变更字段名。

### `reply_rules`

- `id`、`name`、`enabled`、`priority`。
- `keywords`：JSON 字符串数组，去空白、去重，每项最长 50 字符，最多 20 项。
- `reply_text`：固定回复，最长 1000 字符。
- `product_template_id`：可空；非空时仅匹配该商品模板。
- `created_at`、`updated_at`。

匹配顺序固定为：商品专属规则优先于通用规则；同一范围内按 `priority` 降序、`id` 升序；关键词采用不区分大小写的包含匹配。首个命中即停止，不引入正则表达式或脚本规则。

## API 契约

### 配置

- `GET /api/reply-assistant/settings`
- `PUT /api/reply-assistant/settings`

响应包含 `api_key_configured`，不包含 `api_key`。

### 规则

- `GET /api/reply-assistant/rules`
- `POST /api/reply-assistant/rules`
- `PATCH /api/reply-assistant/rules/{rule_id}`
- `DELETE /api/reply-assistant/rules/{rule_id}`

删除规则为物理删除，因为规则没有业务交易引用；删除操作写审计日志。此行为仅作用于回复规则，不影响现有软删除策略。

### 候选生成

`POST /api/reply-assistant/suggestions`

请求：

- `account_id`：必填，只用于验证账号存在并标记审计范围。
- `product_template_id`：可选，用于规则和商品上下文。
- `buyer_message`：必填，去首尾空白后 1–2000 字符。
- `context_messages`：可选，最多 10 条；每条包含 `role=user|seller` 和最长 1000 字符的 `content`。

响应：

- `reply`：候选回复。
- `source`：`rule` 或 `ai`。
- `matched_rule_id`：规则来源时返回，否则为空。
- `risk_level`：`normal` 或 `manual_required`。
- `risk_reasons`：触发人工提示的原因列表。
- `copy_allowed`：始终为 `true`；表示页面允许复制，不代表平台允许自动发送。

接口不接受会话 ID、买家 ID、Cookie 或任意外部 URL。

## 敏感意图与回复策略

以下关键词类别将候选标记为 `manual_required`：

- 改价、最低价、私下付款、转账。
- 退款、退货、投诉、举报、平台介入。
- 电话、地址、身份证、验证码等隐私或认证信息。
- 账号异常、封禁、处罚。

敏感意图识别仅用于提示，不静默丢弃用户输入。规则仍可生成候选，但页面必须显示醒目的“人工核对”提示；AI 系统提示词必须禁止编造价格、库存、物流时间、退款承诺和平台政策。

## AI 调用

- 仅实现 OpenAI-compatible `POST {api_base_url}/chat/completions`。
- 模型请求包含全局系统提示、经过裁剪的商品摘要和用户提供的消息上下文。
- 商品摘要只包含商品模板名称和默认售价；不发送默认成本、利润、客户资料、附件、Cookie、订单原始响应或其他敏感字段。
- 输入总字符数在服务层限制为 12000；超出时从最旧上下文开始裁剪，买家最新消息始终保留。
- 模型返回只读取第一条文本候选，去除首尾空白后限制为 1000 字符。
- 超时、认证失败、限流、无效 JSON 和空响应统一转换为稳定错误码及中文提示，原始响应正文不写日志、不返回前端。
- 不自动重试模型请求，避免重复费用和不确定延迟。

## 安全与隐私

- 所有新接口继续受现有 API Token 中间件保护。
- AI 密钥使用现有 `encrypt_field` / `decrypt_field`，数据库中不保存明文。
- 前端状态、浏览器存储、URL、错误信息和审计日志均不得出现 AI 密钥。
- 审计日志只记录账号 ID、商品模板 ID、来源、风险等级和规则 ID；不记录买家消息、上下文或候选正文。
- 账号必须存在且未软删除；状态为 `paused` 时仍允许生成候选，因为本流程不访问闲鱼网络。页面明确显示暂停状态，不暗示账号可自动运行。
- 外部模型调用前必须由用户显式启用 AI，并完成密钥和模型配置；否则只有固定规则可用。

## 错误处理

- 助手总开关关闭：返回 HTTP 409。
- 输入或配置校验失败：返回 HTTP 400。
- 账号、商品模板或规则不存在：返回 HTTP 404。
- 没有规则命中且 AI 未启用：返回 HTTP 422，并提示配置规则或启用 AI。
- 外部模型认证失败：返回 HTTP 502 和稳定错误码 `AI_AUTH_FAILED`。
- 外部模型限流：返回 HTTP 503 和稳定错误码 `AI_RATE_LIMITED`。
- 外部模型超时或不可用：返回 HTTP 504/502，不泄露第三方响应正文。

前端保留用户已填写内容，错误后可直接修改并重试。

## 测试与验证

### 后端

- 配置密钥加密、掩码读取、保留和显式清除。
- 规则校验、商品专属优先级、通用优先级、关键词归一化和首个命中。
- 敏感意图分类与 `manual_required` 标记。
- 账号/商品边界、助手关闭、无匹配且 AI 关闭。
- AI 请求最小字段、上下文裁剪、错误映射和原始响应脱敏。
- 路由认证、CRUD、审计日志不包含消息正文和密钥。

### 前端

- 服务层请求/错误转换。
- 表单必填、上下文条数限制和配置密钥占位行为。
- 规则候选与 AI 候选的来源展示。
- 敏感意图的人工核对提示。
- 复制候选不会触发任何闲鱼接口或浏览器自动化。
- 新路由在桌面和移动完整导航中可达。

### 验证栈

- 后端定向测试后运行 `python -m pytest server/backend -q`。
- 前端定向测试后运行 `npm test -- --run`。
- 运行 `npm run build`。
- 使用全 API mock 的 Playwright 冒烟验证页面生成、错误保留和复制流程。
- Docker 仅在代码与测试全部通过、且用户确认部署窗口后重建；本阶段验证不得真实调用闲鱼接口。

## 验收标准

- 在未配置 AI 的干净环境中，固定规则可以生成候选回复。
- AI 密钥在 API 响应、前端存储、日志、测试快照和 Git diff 中均不可见。
- 商品专属规则稳定覆盖通用规则，重复请求不会写入买家原文。
- 涉及议价、退款、隐私或账号异常的输入始终显示人工核对提示。
- 生成、编辑和复制候选的全流程不读取 Cookie、不调用 MTOP、不连接闲鱼 IM，也不发送闲鱼消息。
- 后端、前端、构建和页面冒烟验证通过，现有订单同步与业务功能无回归。

## 后续阶段

Chrome MV3 薄桥接将另行设计，预计仅负责当前会话文本读取、候选展示和用户确认后的页面发送。插件不得保存模型密钥或读取 Cookie；是否允许任何自动发送，需要在后续设计中再次确认平台协议、账号风险、去重和紧急停止边界。
